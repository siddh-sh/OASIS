# Localisation

The UI language is chosen in the header and controls every page. All nine
languages — English, Marathi, Malayalam, Gujarati, Kannada, Tamil, Telugu,
Odia and Bengali — are complete, key for key.

**Style: code-mixed, the way people actually write.** Native words where they
are everyday words (மீன்பிடி, हवामान, মাছ ধরা); where there is no everyday native
term, the English word written in the local script (பாஸ்வேர்டு, सर्व्हर, ডেটা), the
way Indian newspapers and apps do. Standard abbreviations stay Latin (SST,
DNA, FAO, p-value, Pearson r).

## How it works

- **One source of truth.** `frontend/src/store/locale.ts` holds the language
  (persisted in `localStorage`, restored on load) and drives i18next.
  `<html lang>` follows it.
- **Dictionaries.** `frontend/src/i18n/locales/<code>.json`, keyed by
  feature (`dashboard.*`, `fisheries.*`, `correlation.*` …). Plurals use
  `_one` / `_other`; inline markup uses `<b>`, `<em>`, `<name>` with `<Trans>`.
- **Typed keys.** `src/i18n/i18next.d.ts` types `t('…')` against `en.json`, so
  a misspelt key fails `tsc`. Keys built from runtime data (a weather code, a
  database role, a region name) go through `tDynamic()` / `placeName()` in
  `src/i18n/dynamic.ts`, which fall back to the raw value.
- **Numbers and dates.** `useFormat()` (`src/i18n/format.ts`). Digits stay Latin
  in every language (scientific values, coordinates and chart ticks read the same
  everywhere); grouping, month and weekday names follow the language.
  Chrome and Edge ship without Odia date data, so `format.ts` carries Odia's
  CLDR month and weekday names and uses them when the browser lacks them.
- **Errors.** `describeError()` / `describeAuthError()` (`src/i18n/errors.ts`)
  give a translated explanation; the server's English `detail` is appended in
  brackets for diagnosis.
- **Model-written text** (chat answers, "Explain in plain language", species
  explanations) is generated in the UI language: the frontend sends `language`,
  the backend adds `language_instruction()` (`backend/app/agents/llm.py`) to the
  prompt, which pins numbers, units and scientific names.
- **Backend captions** that the UI shows are returned as codes the frontend
  translates — correlation `note_codes`, weather `weather_code`, chat
  `fallback_code`, fisheries `other` series `count`.

## What is deliberately not translated

Marked with the standard `translate="no"` attribute in the markup:
scientific names, process IDs, BIN codes, DNA sequences, buoy position codes,
photographer names, licence codes, and the user's own chat messages.
Species names in the reader's language, in order of preference:

1. a **recorded local name** (FishBase / SeaLifeBase / Wikidata, see
   `load_vernacular_names.py`) — e.g. बांगदा for Indian mackerel;
2. otherwise the **English common name written as it sounds** in that script —
   "Wahoo" → वाहू / வாஹூ / ওয়াহু. Generated once per name by
   `data-pipeline/cleaning/transliterate_common_names.py`, stored with source
   `Transliteration`, cached and hand-correctable in
   `seeds/raw/vernacular/transliterations.csv`, and labelled as a phonetic
   rendering on the Species page — never passed off as a local name, and never
   a translation of the meaning;
3. otherwise the scientific name.
Map tiles come from OpenStreetMap and show place names as OSM renders them.

## Adding text

1. Add the key to `en.json` **and** every other locale file (same
   placeholders and tags).
2. Use `t('feature.key')` — the compiler checks it exists.
3. `npm test` runs `locales.test.ts`: every language has exactly the English
   key set, no empty values, and the same `{{variables}}` and tags.

## Browser smoke test

With the backend (:8000) and `npm run dev` (:5173) running:

```bash
cd frontend
npx playwright install chromium   # first time only
npm run test:e2e
```

`e2e/i18n.spec.ts` visits every route in all nine languages, opens the main
panels, and fails on missing keys, page errors, English left in a
regional-language UI (outside `translate="no"`), Indic script left in the
English UI, or a language that does not persist across reload and navigation.
